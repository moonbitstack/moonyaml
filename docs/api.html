Why a document did not become the value the caller asked for.

Two things can go wrong, and they are different things: the YAML may not have been read at all, or it may have been read and not be the shape a type needs. Both carry where — the reader's position, or the path into the document — so a caller can say which line to look at.

The text is not YAML at all: see Refused for the rule it broke.

Shape(@json.JsonDecodeError)

The document read fine and is not the shape the type asked for. The path is a JSON Pointer into what was read, /servers/2/port.

Why a document was refused.

YAML's own answer to ambiguity is to be permissive, which is how a configuration file comes to mean something other than what it looks like. This reader refuses instead: anything it cannot resolve to one reading is an error with a position, never a guess.

Unexpected(At, Char)

A character that cannot stand where it was written.

Truncated(At)

The text ends inside a document: a quote, a bracket or a block scalar that was never closed.

BadEscape(At)

A double-quoted escape that is not one of §5.7's.

BadIndent(At)

A line indented to a column that lines up with nothing.

BadTag(At, String)

A tag nobody has, or a node tagged as something it cannot be.

BadAnchor(At, String)

An alias naming an anchor that was not written before it.

Repeated(At, String)

A key written twice, under duplicates: Reject.

Trailing(At)

A second document where one was asked for.

TooDeep(At)

Nesting past Flavor::depth.

Exceeded(at~ : At, limit~ : Int32, got~ : Int32)

Aliases expanding past Flavor::budget, with the limit and what it reached.

BadUtf8(At)

Not UTF-8, from the byte entry points.

Disallowed(At, String)

A construct this version does not have: a flow collection under the strict dialect, a tag or an anchor under a schema that has none, a key that is a collection where the value tree has only string keys.

pub(all) enum Duplicates {
  Last
  First
  Reject
} derive(Eq, @debug.Debug)

What to do when a mapping names the same key twice.

YAML 1.2.2 §3.2.1.1 says the keys of a mapping are unique and leaves the handling of a duplicate to the processor. Every loader in reach takes the last one, which is what Last does; First and Reject are here because a configuration file with a key written twice is usually a mistake someone would rather be told about.

Last

The last value written for a key is the one the mapping has.

First

The first value written for a key is the one the mapping has.

Reject

A repeated key is refused, with the position of the second one.

What a node is.

An alias is a node of its own rather than a copy of what it names: a document with an anchor and three aliases is three references, and writing it back as twelve copies would be a different document.

Null

An empty node: ~, null, or nothing written at all.

Bool(Bool)

A boolean, which only true and false are under the core schema.

Number(Double)

A string: everything that is not one of the above and was not tagged.

A mapping, as the pairs it was written with: order is part of it, and a repeated key is kept twice.

Alias(String)

A reference to a node written earlier, by the anchor it was given.

pub(all) enum Layout {
  Block
  Flow
  Auto
} derive(Eq, @debug.Debug)

How a collection is laid out.

Block is the style a configuration file is written in: one entry per line, a person can read it and a diff shows one change per line. Flow is the brace and bracket form, which JSON shares and which a machine-generated file often wants. Auto picks per collection: flow when it holds nothing but scalars and the whole of it fits in Style::width, block otherwise. A collection of collections stays block, because that is the shape of a configuration file.

Block

One entry per line, indented.

Flow

{a: 1} and [1, 2], which is JSON's own shape.

Auto

Flow for a collection of scalars that fits in one line, block otherwise.

pub fn Node::events(Self) -> String

One document as the events a parser produces for it: +DOC down to -DOC, with a +MAP/+SEQ for a collection, =VAL for a scalar and =ALI for a reference, each nested one space further in than the event that opened it.

The notation is the YAML Test Suite's, which is where it is specified: the style a scalar was written in is the character before its text (:, ', ", |, >), a flow collection carries {} or [], an anchor &name and a tag <tag> come before the value, and control characters are escaped.

This is the document as a parse rather than as a value: a key that is not a string, a key written twice, two documents in one stream — all of them have events, and none of them has a Json. A caller who wants to know whether two documents are the same *document* rather than the same value can compare these.

pub(all) struct Rules {
  yes_no : Bool
  letters : Bool
  octal : Bool
  binary : Bool
  underscores : Bool
  sexagesimal : Bool
  strings : Bool
} derive(Eq, @debug.Debug)

What a YAML version resolves an unquoted scalar to.

The three released versions disagree with each other, and the disagreements are all here rather than in the scanner: 1.1 reads yes as a boolean, 014 as twelve and 1:30 as ninety, 1.2 reads all three as strings, and StrictYAML reads every scalar as a string whatever it looks like. A version is a set of rules over one reader, which is why this library has one parser and not four.

A dialect nobody has published yet — a configuration language of your own, a pre-1.0 variant — is a Rules of your own, passed through Schema. Nothing here is closed.

yes_no : Bool

yes/no/on/off are booleans (YAML 1.1 §10.3).

letters : Bool

y/n, in either case, are booleans — YAML 1.0 only; 1.1 dropped them.

octal : Bool

A 0 prefix means octal: 014 is twelve (1.1 §10.3); 1.2 spells it 0o14.

binary : Bool

0b1010 is ten (1.1 §10.3).

underscores : Bool

1_000 is a thousand (1.1 §10.3).

sexagesimal : Bool

1:30 is ninety and 1:30.5 is ninety and a half (1.1 §10.3).

strings : Bool

Every scalar is a string, whatever it looks like — StrictYAML's first rule, and the reason a StrictYAML document never surprises a reader.

Values

pub let ancient_rules : Rules

YAML 1.0's, which is 1.1 plus the single letters y and n. The 1.1 revision removed them because a lone n is more often a name than a no.

pub let budget : Int32

How many nodes the aliases in one document may expand to.

An alias can name a node that itself contains aliases, so a dozen lines can expand to billions of nodes: the "billion laughs" shape, which is what YAML's alias facility costs unless something counts. There is no published value to follow, so this takes the safe side — enough for any document anyone meant to write, far short of exhausting memory. Flavor::new(budget=...) raises it, and aliases=false refuses an alias outright.

pub let core : Schema

The core schema of YAML 1.2.2 §10.2: what this package reads.

pub let core_rules : Rules

YAML 1.2's core schema: nothing but true/false, null, and the decimal, 0o and 0x numbers of §10.2.

pub let depth : Int32

How deep a document may nest.

500 is deep enough for any configuration file ever written and shallow enough that a reader which walks the tree cannot be driven off the stack by one that was not. A document that nests deeper than this is not a configuration file, and is refused rather than read.

pub let flow : Style

The same document, all in flow style — the form JSON shares.

pub let indent : Int32

How much a nested level is indented.

Two spaces: what almost every configuration file in the wild uses, and what a reader's eye is trained on.

pub let legacy_rules : Rules

YAML 1.1's type resolution, §10.3 of the 1.1 specification: the booleans, the octal and binary integers, the underscored numbers, and the base-60 form.

pub let strict : Flavor

The preset: refuse what is ambiguous, take the last of a repeated key, expand aliases within the budget.

pub let style : Style

The preset: two-space block style, folded at 80 columns, quoting only what has to be quoted, anchors for what repeats.

Block, not Auto: what this writes is a configuration file, and a configuration file is read one entry to a line. Auto is a knob for output whose reader is a machine.

pub let width : Int32

The column a writer folds at.

80: the width yamllint defaults to, which is itself the width of a terminal and of the Python PEP 8 convention the tooling around YAML grew up beside.

pub fn dumps(Json, style? : Style, rules? : Rules, indent? : Int32, sort? : Bool) -> String

Write a Json tree as a YAML document.

Block style by default, which is what a configuration file is written in and what a person reads. A string is quoted only when plain would read back as something else — a number, a boolean, a null, or not at all — so the output looks like a file someone wrote rather than one a program emitted.

This is the reason to have a writer at all: a generator that builds YAML by joining strings gets the escaping wrong the first time a value contains a colon, and gets the indentation wrong the first time a value is a list.

style says how; indent and sort override the two knobs that change from call to call. A flat parameter wins over the record — see "Configuration" in the README.

pub fn dumps_all(ArrayView[Json], style? : Style, rules? : Rules, indent? : Int32, sort? : Bool) -> String

A stream of documents, each opened by its own ---.

The separator goes before each document rather than between them, which is the one convention that stays correct under concatenation: two streams joined end to end still read as their documents, and appending one is appending lines. A reader of either convention reads this one — a marker before the first document is not an error anywhere — so nothing is given up by choosing it.

pub fn[T : @json.FromJson + ToJson] round_trip(StringView, adjust? : (T) -> Unit, flavor? : Flavor, schema? : Schema) -> String raise Malformed

The three steps a configuration loader actually takes: read what the user wrote, fill in what they left out, write the whole of it back. adjust is where the defaults go, and it is also what says which type this is — a call with no adjust cannot tell.

YAML 1.0's types, which 1.1 inherited but did not always keep: the single letters y and n are booleans here too.

The 1.1 revision dropped the single letters, because a lone n is more often a name than a no: n: 1 in a table of columns is a heading, not a false. A file that says %YAML 1.0 means the older reading.

moonyaml/strict

The strict dialect: block structure only, every scalar a string, no flow style, no anchors, no tags, no repeated keys.

Values

pub let flavor : @moonyaml.Flavor

The preset for reading StrictYAML: a repeated key is a fault.

StrictYAML rejects duplicate keys, and it is right to: a mapping that names the same key twice has no reading that a person could have predicted.

pub let rules : @moonyaml.Rules

How StrictYAML resolves a scalar: as text, always.

This is the whole of StrictYAML's first promise. port: 8080 and port: "8080" are the same string, enabled: yes is the word, and the caller says what a value means by reading it through a schema of its own. Nothing in a document is a number, a boolean or a null because of how it is spelled.

pub let schema : @moonyaml.Schema

StrictYAML's schema: text scalars, no tags, no anchors, no flow style.

Each of those is a feature StrictYAML removes, and each is removed for the same reason — it makes what a document says depend on something other than the text in front of the reader:

  • a tag asks for a type the reader may not have;
  • an anchor makes one node appear in two places, so the document is no longer a

tree you can read top to bottom;

  • flow style packs structure onto a line, which is where the bracket-matching

mistakes come from.

pub fn of(StringView) -> @moonyaml.Schema raise @moonyaml.Refused

The schema a stream asks for.

A document that opens with %YAML 1.1 says how it wants to be read, and 1.1's rules are not 1.2's: yes is a boolean there and a string here, 014 is twelve there and fourteen here. Reading it as 1.2 would silently give the caller a different value from the one the file's author wrote, which is the one failure mode a configuration loader must not have.

No directive means 1.2, which is the current release and what a file written without a version marker means today. A directive naming a major version this library does not have is refused, rather than read with the wrong rules.
