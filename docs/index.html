YAML · MoonBit · Apache-2.0

YAML, read as a value and as a document.

Five versions of the language — 1.2.2, 1.1, 1.0, StrictYAML, and one that reads the version a file asks for — from a single scanner. A version is a resolver here, not a fork. And every one of them can be written back, comments and all.

01 · why

YAML is not a JSON dialect.

It has its own specification, its own versions that disagree about what a word means, and constructs — anchors, tags, block scalars, document streams — with no JSON counterpart. It reads into a Json tree because that is what a caller wants, not because it is the same language. Pretending otherwise is how a configuration file comes to mean something other than what it looks like.

one scanner

Versions are resolvers

The grammar is the same in every version; what differs is what a scalar means. So the scanner is shared, the resolver is a record, and a version is a value you can pass to a function.

two shapes

Value or document

loads gives a Json. parse gives a Node that remembers the comment above a key, the flow style of a short list, the anchor, the tag and the quoting — so emit can write the file back.

refusal

Ambiguity is an error

Everything that cannot be resolved to one reading is refused with a line and a column, rather than guessed at. A tag that is unknown is not dropped: a document that asked for a type and did not get it has not been read.

budget

Billion laughs, bounded

An alias may name a node that holds aliases, so a dozen lines can expand to billions. PyYAML and libyaml perform that faithfully. Here the expansion is counted and capped.

02 · the record

Measured against the YAML Test Suite.

The suite is 402 cases. This build reads 363 of them as the suite says — 271 compared against the JSON the suite gives, 92 refused where it requires a refusal — and answers two differently. Both of those are tab faults that PyYAML, libyaml and ruamel.yaml also read; refusing them would refuse documents that load everywhere else.

Version Same as 1.2.2 Reads differently Refused by both Refused only here
moonyaml — 1.2.2 core 292 0 110 0
yaml11 — 1.1 291 1 110 0
yaml10 — 1.0 290 2 110 0
strict — StrictYAML 155 25 110 112

Every version reads every document 1.2.2 reads, and refuses every document it refuses. Those two columns being zero is the claim the shared scanner makes — and the table is not prose: it is asserted by tests/versions on every run, so a number that moves here fails the build.

03 · the same file, five readings

Where the versions part company.

Four readings of one file, and not one of them is a bug. yes is a boolean in 1.1 and a string in 1.2; 014 is octal twelve in 1.1 and decimal fourteen in 1.2; 12:30 is a sexagesimal only in 1.1. Which of those you meant is a property of the document, not of the reader — so it is a package you choose, not a flag that guesses.

04 · the document

Write the file back the way it was written.

The comment above the document, the comment beside the image line, the anchor on defaults, the alias that stands for its value, the flow style of ports, the block scalar's chomping indicator, the quoting of a string that had to be quoted — all of it is in the tree, and all of it comes back. to_json is there for the caller who wants the value instead, with the merge key folded in and the alias resolved.

The tree is checked against the value tree on the whole suite: 278 of the 292 documents this reader reads agree value for value, and the 14 that do not are listed by id with their reason.

One thing the writer settles rather than keeps: the gap before a trailing comment is written as a single space. Everything else in the two figures above is exactly what went in.

05 · refusing

What it will not guess at.

A reader that is permissive where the specification is ambiguous is a reader that will one day silently read something else. This one raises Refused — a suberror with a position, not a string — and the message says which rule it was.

The check is a property of the parse, not a lint afterwards: nothing is read into a tree that has already been guessed at.
