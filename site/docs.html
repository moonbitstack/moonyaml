Install

One module, five packages. The root package is YAML 1.2.2 and the writer; the others are a version each. 

moon add moonbitstack/moonyaml
PackageWhat it is
moonyaml 1.2.2's core schema, the writer, the document model, the typed codec
moonyaml/yaml11 yes/no booleans, 014 octal, sexagesimals, 1_000, the << merge key
moonyaml/yaml10 YAML 1.0's types, which 1.1 inherited but did not always keep
moonyaml/strict StrictYAML: block structure only, every scalar a string
moonyaml/any The version the document asks for with %YAML, 1.2.2 when it asks for nothing

They are packages rather than a flag because a version is a promise about meaning. Each carries the same loads/loads_all/load/load_all/dumps/dumps_all, so one can be held in a variable and passed to a function.

Reading a value

loads returns a Json — the same tree @json and every other reader in this family use. Mappings become objects, sequences arrays, and a scalar becomes whatever the schema says its text means. 

let config = @moonyaml.loads(
  #|server:
  #|  host: 0.0.0.0
  #|  port: 12000
  #|tags: [http, native]
)

match config {
  Json::Object(m) => println(m.get("server").unwrap().stringify())
  _ => ()
}
  • loads(src) -> Json raise Refused — one document. A second one is Trailing, because a caller expecting one file's worth of configuration should be told it got a stream.
  • loads_all(src) -> Array[Json] — every document in a --- stream, in order. An empty stream is [], not [null]: nothing is not the same as one document containing nothing.
  • load(bytes) / load_all(bytes) — the same over UTF-8, with bom=true skipping a leading byte-order mark (§5.2 permits one, and an editor will write one).

What a plain scalar means is the core schema of §10.2: null/~ is null, true/false are booleans, 123, 0o17, 0x1f, 1e3, .inf and .nan are numbers, and everything else is a string. yes, on, 014 and 12:30 are strings here, because that is what 1.2 says they are. Quoting something makes it a string whatever it looks like, and a tag overrides the schema.

The five versions

The grammar does not differ between versions; what a scalar means does. So the scanner is shared and the version is a resolver, which is why this table can be a measurement rather than a claim.

Version Same as 1.2.2 Reads differently Refused by both Refused only here
moonyaml — 1.2.2 core29201100
yaml11 — 1.129111100
yaml10 — 1.029021100
strict — StrictYAML15525110112

Each is a value of the same shape, so a caller can take one as a parameter:

let config = @yaml11.loads(src)      // yes is a boolean here
let legacy = @yaml10.loads(src)
let plain  = @strict.loads(src)      // and every scalar is a string
let asked  = @any.loads(src)         // %YAML 1.1 at the top decides

any is the only package that guesses, and it guesses once, from the document, at the top. A %YAML 1.1 directive makes it read as 1.1; %YAML 1.2 or no directive at all makes it 1.2.2. A directive naming a version it does not have is refused rather than approximated.

Picking one. Read your own files with moonyaml. Read files you did not write with any. Reach for yaml11 when a file says yes: and means a boolean — Ansible, older Compose files, anything that grew up in the 2000s — and say so in the module that reads it.

The document tree

loads answers what a file means. parse answers what it says. The difference is a Node, which keeps the comment above a key, the comment beside a value, the quoting, the flow style, the anchor and the tag — so the file can be written back. 

let doc = @moonyaml.parse(src)
println(@moonyaml.emit(doc))   // the same document, byte for byte
println(doc.to_json().stringify())  // what it means
FieldHolds
kindNull, Bool, Number, Str, Sequence, Mapping, or Alias(name)
textThe scalar's text exactly as written — trailing spaces, tabs and all
stylePlain, Single, Double, Literal(n), Folded(n), where n is the explicit indentation or 0
flowWhether the collection was written {…}/[…]
anchor, tagThe &name and the resolved tag, or None
before, afterThe comments above the node, and the one after it on its own line — each without its #

A mapping is an Array[(Node, Node)], not a map: order is part of a document, keys are nodes rather than strings, and a file can legitimately have a sequence as a key. An alias stays an alias, so emit writes *shared rather than the several lines it stands for. to_json is there for the caller who wants the value: it folds << in and resolves the aliases.

Build one by hand, or from a value:

let doc = @moonyaml.Node::map([
  (@moonyaml.Node::scalar("name"), @moonyaml.Node::scalar("web")),
  (
    @moonyaml.Node::scalar("ports"),
    @moonyaml.Node::seq([
      @moonyaml.Node::scalar("80"), @moonyaml.Node::scalar("443"),
    ]).commented(before=["what it listens on"], after=""),
  ),
])

let built = @moonyaml.Node::of_json(@moonyaml.loads(src))

emit takes indent (default 2) and from (default 0), the column it starts at when the text is going inside something else.

Typed values

A YAML file usually has a shape someone already wrote down. Through @json.FromJson and ToJson — the traits a Json value already uses — a document becomes that record and back: 

let server : Server = @moonyaml.loads_as(src)
let yaml = @moonyaml.dumps_of(server)
let again = @moonyaml.round_trip[Server](src, adjust=fn(s) {
  s.port = 8081
})

loads_as and load_as raise Malformed, which has two arms: Read(Refused) when the text is not YAML, and Shape(JsonDecodeError) when it is YAML of the wrong shape. Keeping them apart is the difference between "this file is broken" and "this file is not a Server", which is the difference between a bug and a misconfiguration.

round_trip is a test helper, not a converter: it decodes, lets adjust change the value in place, writes it back and returns the text — so a decode that loses a field shows up as a missing line in the output rather than as a surprise in production.

Writing

dumps writes block style at indent 2, quoting only what has to be quoted. Every choice it makes is a field of Style. 

@moonyaml.dumps(value)                       // block, indent 2, width 80
@moonyaml.dumps(value, style=@moonyaml.flow)  // JSON's own shape
@moonyaml.dumps(value, indent=4, sort=true)   // flat parameters win
@moonyaml.dumps_all([a, b])                  // each opened with ---
StyleDefaultWhere the default comes from
indent2What Kubernetes manifests and Compose files use; the value kubectl writes
width80Where a flow collection stops fitting on a line
layoutBlockBlock reads better in a diff. Flow is JSON's shape, Auto decides per collection by width
quotesMinimalQuote only what has to be quoted, which is what a person writing YAML does
anchorstrueA collection that appears twice is written once and referenced — what PyYAML and ruamel.yaml do with a shared object
sortfalseA document keeps the order it was written in. Turn it on for a stable file

A value that has an alphabetically reasonable shape is still written in the order it has, unless sort says otherwise. A string that could be read as a number, a boolean, a null or a tag is quoted; a string with a newline in it becomes a literal block with the chomping indicator that reproduces it exactly.

dumps also takes rules, so a 1.1 Json tree can be written with 1.1's spellings — yes for a boolean, 014 for twelve — rather than 1.2's.

Changing a default

Two records, each with presets, each field overridable, and every knob also reachable as a named argument on the call. The order is preset, then record, then flat argument: a flat argument wins over a field of the record, which wins over the preset's value. There is no other way to change a default, and no default is hidden. 

@moonyaml.loads(src, flavor=@moonyaml.Flavor::new(duplicates=Reject))
@moonyaml.loads(src, flavor={ ..@moonyaml.strict, budget: 1000 })
@moonyaml.dumps(value, style=@moonyaml.Style::new(quotes=Single))
FlavorDefaultWhy
depth500Between Jackson's 1000 and serde_json's 128, and the same as this family's JSON reader
duplicatesLastWhat every loader in reach does. First and Reject exist because a key written twice is usually a mistake
aliasestrueAn alias is part of the language; false refuses one outright
budget10 000 000Nodes one document's aliases may expand to. There is no common value to follow, because libyaml and PyYAML have none, so this takes the safe side

The budget is the "billion laughs": an alias may name a node that contains aliases, so a dozen lines can expand to billions of nodes. PyYAML's safe_load and libyaml both perform the expansion faithfully. Here it is counted and capped, and going over is Exceeded with the node count and the limit, not an out-of-memory.

Refusals

Refused is a suberror with twelve arms, each carrying an At — byte offset, line and column — so a caller can match on the kind of fault rather than read a string:

ArmWhen
Unexpected(at, c)A character that cannot appear here
Truncated(at)The text ends inside a document
BadEscape(at)A double-quoted escape that is not one of §5.7's
BadIndent(at)A line indented to a column that lines up with nothing
BadTag(at, tag)A tag nobody has, or a scalar tagged as a collection
BadAnchor(at, name)An alias naming an anchor that was not defined
Repeated(at, key)The same key twice, when duplicates is Reject
Trailing(at)A second document, from loads
TooDeep(at)Past depth
Exceeded(at, limit, got)Aliases expanding past budget
BadUtf8(at)Not UTF-8, from the byte entry points
Disallowed(at, what)A construct the version does not have — a flow collection in StrictYAML, an anchor, a tag

Show prints them as a position and a sentence:

a: [1, 2      1:4: ends mid-document
a: *nope      1:4: no anchor named `nope`
a: 1
a: 2          2:1: the key `a` is written twice

A tag from a vocabulary this reader does not have is not one of these. §10.4 permits a processor to resolve such a node as if it carried no tag, and that is what happens, so !!python/object 1 reads as the number 1 rather than failing the file. parse keeps the tag on the node, so it survives a write.

The test suite

The YAML Test Suite is 402 cases: a document, the JSON it should read as, and sometimes the marker that it must be refused. This reader answers 363 of them as the suite says — 271 against the JSON, 92 by refusing — and reads two that the suite refuses, both tab faults that PyYAML, libyaml and ruamel.yaml read too.

The comparison is a test rather than a script, in four parts:

  • the suite as 1.2.2, case by case, in src/tests/core
  • the suite beside 1.2.2, for every version, in src/tests/versions — the table above is its output, asserted, so a number that moves fails the build
  • the document model beside the value model over the same suite: 278 of 292 documents agree, and the 14 that do not are listed by id with a reason
  • the divergence lists, which fail in either direction: a new difference is a decision, and a listed difference that starts passing is a stale claim
moon test --target all                  # everything, four backends
python3 tools/gen_suite.py              # regenerate the suite data
python3 tools/sync_diverged.py          # rewrite a divergence list from a run
